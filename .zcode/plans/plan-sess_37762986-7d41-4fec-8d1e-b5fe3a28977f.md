## Context
Rename the product’s displayed brand from **Kognit** to **Kogni** throughout the application, browser/page metadata, and documentation without breaking existing users’ local data or deployed Firebase configuration.

This will be a display-brand rename, not a destructive identifier migration. Existing storage keys, cache/database names, API service IDs, deployment parameters, emulator namespaces, and the Firebase project ID `kogni-ai` will remain stable.

## Implementation
1. Replace user-visible `Kognit` branding with `Kogni` in application UI, including navigation, loading/auth/onboarding screens, profile/community fallbacks, portal/share text, privacy notices, AI/BYOK disclosures, and error messages.
2. Update page/document metadata such as `app/layout.tsx` and legacy `index.html` so browser titles display `Kogni`.
3. Update prose branding in `README.md` and `PRIVACY.md` while preserving code-form compatibility identifiers documented there.
4. Rename private npm package metadata to `kogni` / `kogni-functions` and synchronize both package lockfiles. Rename the compile-time-only `KognitDB` TypeScript type to `KogniDB` for code consistency.
5. Deliberately preserve:
   - `kognit_*` localStorage keys so theme, XP, streak, and review-event state are not lost;
   - `kognit-shell-v1` so the service-worker cache is not needlessly invalidated;
   - `FlashcardAppDB` and its schema;
   - `kognit-api`, `kognit-next-admin`, and `KOGNIT_PRIVACY_VERSION` stable integration identifiers;
   - `demo-kognit-*` test namespaces;
   - all `kogni-ai` Firebase project/domain/database identifiers, which already match the new brand and cannot be renamed as ordinary text.
6. Add or update focused assertions for page metadata and key brand surfaces while retaining tests that protect legacy compatibility identifiers.

## Critical files
- `app/layout.tsx`, `index.html`
- Representative UI files under `src/components/`, `src/routes/`, `src/router/`, and `src/context/`
- `README.md`, `PRIVACY.md`
- Root and Functions `package.json` / lockfiles
- `src/types/domain.ts`, `src/lib/db.ts`, and related type-only tests
