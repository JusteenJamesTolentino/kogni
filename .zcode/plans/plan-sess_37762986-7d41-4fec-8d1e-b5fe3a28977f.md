## Context
The visited-player UI already includes Followers/Following and a Published decks section, but its deck source depends on Firebase trigger-maintained projections that are unreliable in the selected Vercel-only architecture. The signed-in user’s own `/profile` has no social counts. The browser also repeatedly reports duplicate React keys `6` and `8`; the likely sources are malformed leaderboard identities and insufficient validation of legacy online-deck card identities.

Confirmed scope:
- Your own profile shows **Followers and Following counts only**.
- Another player’s profile shows **active public published decks** only.
- Another player’s browser-local imported, copied, AI-generated, or manually created decks remain private and cannot be listed.
- Fix the repeated duplicate-key warnings as part of this work.

## Implementation
1. **Add an owner-only social summary.**
   - Add a shared service in `functions/src/social-core.ts` that validates the current caller, counts canonical incoming/outgoing `playerFollowEdges`, and returns only `{ followerCount, followingCount }`, including when the owner has disabled discoverability.
   - Expose it via authenticated `GET /api/players/me/social-summary`, reusing Admin authentication, database deadlines, private cache headers, and sanitized errors from `app/api/_lib/*`.
   - Add strict browser response types/validation and a request helper in `src/lib/social.ts`.

2. **Show social counts on the signed-in profile.**
   - Load the owner summary in `ProfileRoute` with stale-request protection and explicit loading/error behavior.
   - Add Followers and Following to the existing `Profile.stats` grid while preserving local deck/card/due/XP statistics.
   - Keep counts non-clickable and never expose follower identities.

3. **Provide trusted Vercel-only public deck listing.**
   - Add a shared service that enforces current caller eligibility, target privacy/discoverability, and either-direction block checks before reading decks.
   - Query bounded canonical `onlineDecks` heads by `head/ownerId`, then produce safe metadata with existing `buildPublicOnlineDeckProjection` from `functions/src/projections.ts`.
   - Include only target-owned, active, public decks—never cards, answers, study guides, schedules, unlisted/private decks, or local-library data.
   - Add authenticated `GET /api/players/[uid]/decks` with newest-first keyset pagination using `{ updatedAt, id }` and a real 21st-row `hasMore` sentinel.
   - Revalidate target eligibility and blocks at the response boundary so opt-outs and blocks fail closed without Firebase triggers.

4. **Wire the visited-player UI to trusted APIs.**
   - Update `PublicPlayerRoute` to require the trusted profile response before loading presence and published decks.
   - Remove the legacy `getPublicAccountByUid` fallback and direct `onlineDecksByOwner` read from this route.
   - Preserve generic unavailable behavior for private/stale/blocked targets.
   - Reuse the existing `PublicPlayerProfile` cards and `onlineDeckPath`; add load-more/pagination state so lists do not silently stop at 20.

5. **Fix duplicate React keys at the data boundaries.**
   - Harden `rankedEntries` in `src/lib/leaderboard.ts`: require each embedded UID to match its Firebase child key and defensively deduplicate canonical UIDs before ranking. Keep stable UID React keys rather than using array indexes.
   - Harden online-version parsing in `src/lib/onlineDecks.ts`: require each card object key to equal `card.id`, enforce unique contiguous card orders, and require `cardOrder` to map exactly to the validated cards.
   - Reject malformed legacy data through existing unavailable/error states instead of rendering duplicate identities.
   - Use a composite study-step key only as a final UI safeguard; boundary validation remains authoritative because duplicate card IDs would also corrupt review identity and deduplication.

6. **Rules and documentation.**
   - Add/verify the server query index for `onlineDecks` by `head/ownerId`; do not add client read privileges.
   - Update README API/privacy documentation for owner-only social counts, published public decks, pagination, and malformed legacy data handling.
