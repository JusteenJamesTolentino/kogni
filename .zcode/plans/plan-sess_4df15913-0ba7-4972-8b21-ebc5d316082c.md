## Context

Deck generation fails at `src/lib/gemini.ts:157–160` because literal-answer coverage is enforced with an immediate exception and no recovery. A guide may explain an answer using different wording, or lose answer text when truncated to 8,000 characters. The app consequently discards an otherwise valid 30-card result.

Keep the requirement that answers are findable in the study guide, but replace this dead-end with a bounded, transparent recovery flow.

## Implementation

### 1. Separate structural validation from final coverage validation

In `src/lib/gemini.ts`:

- Validate exactly 30 usable, distinct cards first and preserve that normalized candidate when guide coverage fails.
- Keep `normalizeGeneratedDeck` strict for verified final results; do not return a falsely verified deck.
- Report missing answer phrases as structured internal coverage data rather than matching exception strings.
- Detect oversized guides explicitly so truncation is not mistaken for an unexplained model failure.

### 2. Add one optional, same-model guide repair

- Before generation, show an unchecked option: **Automatically repair the study guide once if needed — may use additional Gemini quota.**
- If enabled and coverage fails, make at most one guide-only repair request to the same configured model.
- For file import and regeneration, retain the original file part in the repair request. For creator continuations, reuse the disclosed topic/guide reference context.
- Include the candidate guide and card facts as untrusted data. Ask for natural explanatory prose containing all complete answer phrases within the existing guide limit.
- Preserve all 30 cards unchanged. Do not regenerate questions, switch models, append a fabricated answer bank, or introduce unsupported source facts merely to satisfy matching.
- Validate the repaired guide against **all** answers, not only the initially missing ones. Assign `literal-answers-v1` only after success.
- Add a clear live-log stage for guide repair and apply a timeout. Do not loop or retry indefinitely.

### 3. Preserve recoverable results

Update `MagicImport.tsx`, regeneration, and continuation callers:

- If automatic repair is disabled, fails, or remains incomplete, retain the candidate in memory instead of forcing a full-generation restart.
- Show an actionable message and **Repair study guide** button that explicitly authorizes one additional request per click.
- Keep retry limited to guide repair; no automatic repeated retries.
- Save/publish remains unavailable until guide coverage passes. Existing source selection and the candidate remain available while the page stays open.
- Show provider failures separately from coverage failures, with no API-key or source-content logging.

### 4. Align text matching and prompts

In `src/lib/studyGuideCoverage.ts`:

- Preserve boundary-aware matching, Unicode, case, quotes, meaningful symbols, and numeric safety.
- Make typographic hyphen/space normalization consistent with the disclosed contract.
- Continue rejecting semantic paraphrases as proof; the repair step supplies the necessary canonical wording instead.
- Strengthen both generation prompts to prefer short answer phrases and self-contained guides that cover all 30 answers.

### 5. Regression tests and documentation

Add tests covering:

- A 30-card result with six uncovered answers is retained and successfully repaired.
- Successful first-pass coverage makes no extra request.
- Automatic repair requires explicit opt-in and uses the same model/source.
- Repair never changes cards or bypasses exact-30/duplicate validation.
- Oversized guides produce a recoverable length issue.
- A repair omitting another answer remains unverified.
- Repair errors/timeouts retain the candidate; no automatic loop occurs.
- Manual repair does not regenerate the full deck.
- Import, regeneration, and continuation share the recovery behavior.
- Progress/error messages exclude keys and Base64 content.

Update BYOK/help documentation to explain optional additional quota use and that legacy decks are not modified automatically.
