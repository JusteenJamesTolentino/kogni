## Context
You want to remove offline decks and avoid the broken local-deck → publish-online flow.

The unavailable page currently hides every loading failure behind the same message (`src/routes/OnlineDeckRoutes.tsx`). One concrete reader defect can explain a successful publish followed by this screen: `cardOrder` is written with sequential numeric keys, which Firebase can return as an array, but `isValidOnlineDeckVersion` rejects arrays (`src/lib/onlineDecks.ts`). This needs an actual Firebase round-trip regression test; a production permission failure has not yet been confirmed.

The recommended outcome is **account-backed decks only for normal use**, with existing device data preserved—not deleted or silently uploaded.

## Implementation

### 1. Fix publication and cloud reads first
- Normalize Firebase’s array/object representation of ordered collections before validating them. Preserve strict checks for IDs, order, card count, and ownership.
- Test create → read → edit → read against the database emulator, including numeric legacy card IDs and omitted empty distractors.
- Distinguish missing content, invalid records, denied access, and connectivity failures. Add retry without exposing restricted deck details.
- Stop treating every failed head lookup as a never-published deck; permission/network failures must not trigger replacement creation.

**Critical files:** `src/lib/onlineDecks.ts`, `src/routes/OnlineDeckRoutes.tsx`, `test/lib/onlineDecks.test.ts`, `test/lib/database.rules.test.ts`.

### 2. Make the main library account-backed
- Add an authenticated, owner-only library endpoint using the existing `requireUser`, `databaseWithDeadline`, and bounded indexed owner-query patterns. Return metadata, including private decks; do not repurpose or weaken the public player-decks endpoint.
- Load cloud decks and per-user schedules in `AppShell`, clearing stale state and cancelling listeners/requests on account changes.
- Point dashboard actions, counts, and deck links at cloud content. Keep public discovery separate from the personal library.

**Critical files:** new `app/api/decks/route.ts` and owner-library service, `src/routes/AppShell.tsx`, `src/components/Dashboard.tsx`, `src/routes/routeScreens.tsx`, `src/lib/vercel-api.ts`.

### 3. Replace local save/edit/import paths
- Manual creation and Magic Import save directly through `createOnlineDeck`; editing uses the cloud version plus the existing `DeckEditor` and `publishOnlineDeckVersion`.
- New personal decks are private by default, with a deliberate public-publish action. Set `offlinePolicy: { allowed: false, maxQuestions: 0 }`; retain the field for existing-record compatibility.
- Preserve stable card IDs during edits and reject stale versions instead of overwriting another tab’s changes.
- Shared-deck and portal imports remain independent copies, but save into the recipient’s private cloud library rather than IndexedDB. Sharing reads cloud content.
- Replace any exposed continuation action’s local-draft prerequisite with the existing `publishReviewedSeriesDraft` utility, retaining owner/access checks.
- Await confirmed saves before navigation. Keep failed drafts available, use bounded waiting with clear pending/error states, and reuse IDs when reconciling a timed-out save so retry cannot create duplicate decks.

**Representative files:** `src/components/MagicImport.tsx`, `src/components/DeckEditor.tsx`, `src/routes/OnlineDeckRoutes.tsx`, `src/routes/OnlineSeriesRoutes.tsx`, `src/routes/PortalRoute.tsx`, `src/routes/routeScreens.tsx`.

### 4. Keep scheduled study functional online
- Reuse `resetScheduleForChangedContent`, `recordOnlineReview`, and the existing SM-2 calculation. Inject persistence into `StudySession` instead of its hardcoded IndexedDB writer.
- Support due reviews and practice from cloud decks. Practice remains schedule/XP-free; scheduled review advances only after its write is confirmed.
- Keep sessions pinned to their loaded version. Test duplicate-event retries, schedule conflicts, changed-content resets, and revoked/deleted-deck access.
- Update relevant schedule rules if needed; do not loosen private deck access or assume publication’s transaction issue also applies to schedule transactions.

**Critical files:** `src/lib/onlineSchedules.ts`, `src/components/StudySession.tsx`, online study routes, `database.rules.json`, schedule/rules tests.

### 5. Remove offline features without losing existing decks
- Remove “Save offline,” offline limits, local-publish prerequisites, and normal local creation/edit/regeneration/study entry points.
- Preserve IndexedDB decks, cards, schedules, and provenance untouched. Provide a small **Legacy decks on this device** recovery view, outside the main library.
- Offer an explicit preview-and-confirm copy into a private cloud deck. Make this resumable/idempotent; never delete the source. Explain that cloud progress starts fresh and the old schedule remains archived.
- Keep theme, sidebar, Gemini settings, and login persistence—they are not offline decks. Normal cloud operation must not require IndexedDB to be available.
- Update onboarding/privacy copy and maintain `README.md` with the required Overview, Setup & Dependencies, Architecture & Data Flow, Usage & API Reference, and Error Handling & Edge Cases sections.
