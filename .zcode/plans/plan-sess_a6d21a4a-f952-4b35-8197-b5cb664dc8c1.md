## Context

The project began as Vite + React TypeScript, but the completed Kognit implementation currently runs from `src/main.jsx` while stale Vite starter files remain at `src/main.tsx` and `src/App.tsx`. As a result, the actual application is not type-checked. The implementation should be migrated back to strict TypeScript without changing its behavior, Firebase rules, IndexedDB schema, Gemini API usage, or UI.

## Migration plan

1. **Define shared application types**
   - Add `src/types/domain.ts` for canonical `StoredDeck`, `StoredCard`, SM-2 progress, generated deck/card inputs, leaderboard entries, app views, themes, import status, and review quality.
   - Add a small `src/lib/errors.ts` helper to safely convert caught `unknown` values into user-facing messages.
   - Add `src/vite-env.d.ts` declarations for optional `VITE_FIREBASE_*` values.

2. **Convert and strongly type core modules**
   - Replace `src/lib/db.js` with `db.ts`, defining an `idb` `DBSchema` for the existing `decks` and `cards` stores and retaining current per-user ownership enforcement.
   - Convert `sm2.js`, `gemini.js`, `firebase.js`, and `leaderboard.js` to `.ts` with explicit runtime-boundary types.
   - Keep Gemini normalization accepting `unknown`, use the verified `@google/genai` v3 browser API, and type the strict `responseJsonSchema` without weakening runtime validation.
   - Type Firebase transactions, server timestamps, subscriptions, leaderboard records, and award results.

3. **Convert React context and components**
   - Replace `AuthContext.jsx` with `AuthContext.tsx`, using Firebase `User`/`UserCredential`, a typed context value, and `ReactNode` props.
   - Convert every file in `src/components/` to `.tsx` with explicit props, refs, browser/React events, state unions, and Lucide icon types.
   - Preserve the current compatibility fallbacks for display data while using canonical stored types at persistence boundaries.
   - Type study ratings as the 0–5 quality union and keep the current due-only XP behavior.

4. **Replace the real app entry files**
   - Replace the stale starter `src/App.tsx` and `src/main.tsx` with typed versions of the completed application.
   - Explicitly type application state (`AppView`, `Theme`, deck/card arrays, nullable active deck) and all handlers.
   - Update internal imports to be extensionless and consistent.
   - Remove the replaced `.js/.jsx` implementation files only after their typed counterparts are present.

5. **Convert tests and enforce strict compilation**
   - Rename the three library tests to `.test.ts` and type fixtures without weakening the tested runtime validation.
   - Install `@types/canvas-confetti`, since `canvas-confetti` has no bundled declarations.
   - Enable `strict` in both TypeScript configs.
   - Add `npm run typecheck` and restore `npm run build` to `tsc -b && vite build`, ensuring the real application—not only Vite transpilation—is checked.

6. **Update entry/configuration and clean stale starter files**
   - Point `index.html` to `/src/main.tsx`.
   - Update Tailwind content scanning to `ts`/`tsx` files.
   - Remove stale Vite starter-only files/assets (`src/App.css`, starter images, and unused `public/icons.svg`) after verifying they are unreferenced; retain the favicon.
   - Update README language where it currently refers to JavaScript rather than TypeScript.

## Critical files

- New contracts: `src/types/domain.ts`, `src/lib/errors.ts`, `src/vite-env.d.ts`.
- Typed core: `src/lib/db.ts`, `sm2.ts`, `gemini.ts`, `firebase.ts`, `leaderboard.ts`.
- Typed UI: `src/App.tsx`, `src/main.tsx`, `src/context/AuthContext.tsx`, and all `src/components/*.tsx`.
- Configuration: `tsconfig.app.json`, `tsconfig.node.json`, `package.json`, `index.html`, `tailwind.config.js`.
- Tests: `src/lib/*.test.ts`.

## Verification

1. Run `npm run typecheck` under strict TypeScript and fix every error without `any` escape hatches.
2. Run all unit tests, Oxlint, production build, and `npm audit`.
3. Recompile Realtime Database rules in the Firebase emulator to confirm the unrelated migration did not disturb deployment configuration.
4. Start Vite and browser-check the desktop/mobile Google sign-in boundary plus authenticated application rendering where an existing session is available.
5. Search for remaining application `.js/.jsx` imports/files and verify only appropriate tool configuration remains JavaScript.
